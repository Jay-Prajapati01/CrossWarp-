# Windows bridge

Windows-native components live in focused subprojects. The Raw Input/`SendInput` bridge in [input-bridge](input-bridge/README.md) is linked into the Windows Rust agent. The opt-in local diagnostic only counts event kinds; it is not the universal input-sharing path. The window-capture bridge enumerates visible titled windows and reads bounded BGRA frames through Windows.Graphics.Capture. After source approval, the desktop encodes frames as bounded JPEG and sends them over the authenticated window-video lane; the receiver separately approves. The protocol-v6 receiver now offers pointer, wheel, and keyboard controls scoped to the selected visible HWND through ordinary `SendInput`, and the UI can open the proxy in a separate native Tauri window. These source paths build and have unit/contract coverage but have not passed a physical two-PC test. Unified focus ownership and the IDD display driver remain incomplete. See [feature status](../../docs/FEATURE_STATUS.md) and the [documentation index](../../docs/README.md).
