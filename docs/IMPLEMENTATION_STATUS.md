- **Rust agent — PARTIAL:** typed protocol, four-service coordinator, hit-tested surface ownership, balanced input release model, Ed25519 challenge proof and two-sided approval model, authenticated async stream handshake, directional ChaCha20-Poly1305 frames, bounded QoS queue, capability-rooted Shared Workspace operations, and DPAPI identity/trusted-peer stores are implemented. Protocol v4 is current: it retains the v3 first-time-pairing versus trusted-reconnect discriminator and adds pointer coordinates to wheel events. The desktop now lists DPAPI-pinned peer identities and offers reconnect for discovered saved peers; the listener accepts reconnect only when the fresh signature proves the previously stored key, while new pairing still requires both users' code approval. Peer-store errors fail closed on the listener path. Pairing binds both identities, fresh nonces, ephemeral X25519 keys, user-approved code, and signatures. Typed bidirectional Shared Workspace RPC supports browse, bounded reads, folder creation, confirmed rename/delete, sequential SHA-256 uploads, and explicit-confirmation atomic replacement of an existing regular file; the desktop exposes these operations on the live peer session. A session multiplexer routes encrypted records into bounded input, window-video, display-video, and file channels, prioritizes interactive traffic while reserving file progress, and closes child workers when canceled. The desktop owns all service channels but consumes only file RPC. The typed input-session contract binds ordered input events to a session and target device, validates balanced key/button transitions, creates release events on disconnect, and routes releases to their original surface owner. The native adapter preserves event-time screen coordinates, extended-key state, and horizontal-wheel state while translating capture records into typed session events. `InputSessionController` combines ownership with encrypted sending, but native capture, desktop consent, suppression and receiving-side injection remain disconnected. The opt-in local diagnostic starts native capture after explicit consent and reports event-type counts only. The typed media contract sends binary video payloads with a bounded metadata header and validates both video lanes and stale-frame-aware sequencing; it has no capture, codecs, rendering, or desktop consumers. Current agent tests: **59 passed**; native bridge rebuild and its CTest contract test pass. Prior tests cover trusted reconnect without a pairing prompt, first-time pairing's two-sided approval, unknown reconnect rejection, typed window/display frames crossing authenticated encrypted lanes alongside file work, binary media round-trip, input/media frame validation, bounded queues, display progress under input/window load, session cancellation cleanup, and protocol rejection. Physical mDNS discovery, pairing UI, reconnect and cross-PC file operations remain unverified.
